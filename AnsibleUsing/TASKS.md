Репозиторий LightHouse находится по ссылке.

***Часть 1 (использование Ansible)***
1) Допишите плейбук: нужно сделать еще один плей, который установит и настроит LightHouse.
2) При создании задач рекомендую использовать модули: get_url, template, yum, apt.
3) Задачи должны: скачать статические файлы LightHouse, установить Nginx или любой другой веб-сервер, настроить его конфигурацию для открытия LightHouse, запустить веб-сервер.
4) Подготовьте свой файл инвентаризации prod.yml.
5) Запустите ansible-lint site.yml и исправьте ошибки, если они есть.
6) Попробуйте запустить плейбук в этом окружении с флагом --check.
7) Запустите плейбук в prod.yml окружении с флагом --diff. Убедитесь, что изменения в системе внесены.
7) Повторно запустите плейбук с флагом --diff и убедитесь, что плейбук идемпотентен.
8) Подготовьте README.md-файл для своего плейбука. В нём должно быть описано, что делает плейбук, какие у него есть параметры и теги.
9) Готовый плейбук выложите в свой репозиторий, поставьте тег 08-ansible-03-yandex на коммит с фиксацией изменений, а в ответ предоставьте ссылку на него.



Создайте два пустых публичных репозитория в любом из своих проектов: vector-role и lighthouse-role.

***Часть 2 (работа с Roles)***
Ваша цель — разбить ваш плейбук на отдельные роли.
Задача — создать роли для ClickHouse, Vector и LightHouse и написать плейбук для использования этих ролей.
Ожидаемый результат — три ваших репозитория: два с ролями и один с плейбуком.

Что нужно сделать:

1) Создайте в старой версии плейбука файл requirements.yml и заполните его содержимым:

---
- src: git@github.com:AlexeySetevoi/ansible-clickhouse.git
  scm: git
  version: "1.13"
  name: clickhouse
  
2) С помощью ansible-galaxy скачайте эту роль.
3) Создайте новый каталог с ролью с помощью ansible-galaxy role init vector-role.
4) На основе задач из старого плейбука заполните новую роль. Разнесите переменные между vars и default.
5) Перенесите нужные шаблоны конфигураций в templates.
6) Опишите в README.md обе роли и их параметры. Пример качественной документации ansible role по ссылке(https://github.com/cloudalchemy/ansible-prometheus).
7) Повторите шаги 3–6 для LightHouse. Помните, что одна роль должна настраивать один продукт.
8) Выложите все роли в репозиторий. Расставьте теги, используя семантическую нумерацию. Добавьте роли в requirements.yml в плейбук.
9) Переработайте плейбук с учетом ролей. Не забудьте про зависимости LightHouse и возможности совмещения roles с tasks.
10) Выложите плейбук в репозиторий.
11) В ответе дайте ссылки на оба репозитория с ролями и одну ссылку на репозиторий с плейбуком.
